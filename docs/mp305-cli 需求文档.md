# mp305-cli 需求文档

面向连接 ISDT MP305A 或 MP305B 的硬件调试工位，目标支持 Windows、Linux 和 macOS。当前仅在 Windows 上进行实机调试和验收。智能体和脚本通过 USB 查询电源状态、设置直流输出参数并控制输出开关，通过状态回读确认操作结果。

## 跨平台交付

- Windows 首版交付 x64 可执行文件 `mp305-cli.exe`，可从 PowerShell 或 CMD 直接运行。Linux 和 macOS 各自交付可从终端直接运行的 `mp305-cli`。各平台均无需另外安装语言运行时。
- 各平台共用 CLI 命令、JSON 输出和协议解析。USB HID 访问由平台适配层负责。
- 记录构建命令、发布产物和运行依赖。
- 提供 `--help` 和 `--version`。正常结果输出到 stdout，错误诊断输出到 stderr。支持 `--json` 返回稳定、可解析的字段，成功退出码为 0，失败返回非 0。

## 技术选型

- 使用 Rust 实现，使用 Cargo 构建。Windows x64 的发布构建使用 `cargo build --release`。
- 使用 `hidapi` 访问 USB HID。Windows 优先采用 `windows-native` 后端，Linux 和 macOS 的 HID 后端及设备访问权限在对应平台调试时验证。
- 报文编解码与 HID 访问解耦。先用文档中的实测帧验证编解码，再在 Windows 实机上验证 `info` 和 `status`，随后验收输出控制。

## USB 通信

- 使用 USB HID。在当前平台枚举已连接设备，筛选 `VID 28E9`，并根据已知 PID `028A`、HID 用途 `01:04` 或产品名 `MP305A` / `MP305B` 定位候选。查询硬件信息后，只接受这两个型号。多个候选时要求显式选择设备。
- 除 `list` 的只读枚举外，使用主机上的公共锁串行执行 USB 请求。同一主机上有其他 CLI 进程持锁时返回 `device_busy`。读取超时为 2 秒，收到有效但命令码不匹配的回包时在超时范围内继续等待。
- 报告找不到设备、访问失败、超时、报文无效和设备拒绝等错误。写入后无法回读时，返回失败并标明设备状态未知。

## CLI 功能

| 命令 | 行为 |
| --- | --- |
| `list` | 列出匹配的 USB HID 设备和选择标识。无设备时返回空列表。 |
| `info` | 查询型号和固件版本。 |
| `status` | 读取实测电压、电流、功率，以及设定电压、限流、输出开关和工作模式。电压单位为 V，电流单位为 A，功率单位为 W。`mode: 0` 表示直流模式。 |
| `set --voltage <V> --current <A>` | 校验设定值和调试工位配置的上限。在输出关闭时更新设定值，回读确认设定值及输出状态。 |
| `on` | 核对当前设定值符合工位上限，显式开启输出并回读确认。 |
| `off` | 关闭输出并回读确认。 |

只找到一个候选设备时自动选择。多个候选时用 `--device <id>` 指定 `list` 返回的标识。

首版覆盖直流稳压模式。读写成功以设备回包和所需的状态回读为依据。

## 电压和电流保护

- 设定电压和限流值必须来自用户明确指令或该被测硬件已批准的测试配置。智能体不得自行推断、试探或调整设定值。
- 调试工位的最高允许电压和最大允许电流由负责人按被测硬件规格配置。智能体不得修改这些上限，CLI 控制命令不得提供覆盖参数。更换被测硬件后须重新确认适用配置。
- CLI 在发送任何改变设定值或开启输出的报文前，必须校验目标值和适用上限。保护配置位于可执行文件同目录，文件名为 `mp305-limits.json`。MP305A 在该文件不存在时可读取旧名 `mp305a-limits.json`。
- 配置里的 `device_id` 绑定 USB 电源，工位负责人确认实际接入的被测硬件及其适用上限。配置缺失、无效、电源 ID 不匹配或目标值超限时，拒绝设值和开启输出。仍可读取状态，直流模式下仍可关闭输出。
- 修改设定值前须回读确认输出已关闭。开启输出前须重新回读设定值并校验上限。校验失败时停止操作，不得自动改值后重试。

## MP305 USB HID 协议

### 帧格式

报告字节序列为 `Report ID | N | AA | GROUP | L | CMD | DATA | CHK | 填充`。下表中的字节偏移包含 Report ID。多字节数据字段按小端解码。

| 偏移 | 字段 | 含义 |
| --- | --- | --- |
| 0 | Report ID | Windows 实测请求为 `01`，MP305A 响应为 `02`。解析器兼容公开资料中的响应 ID `01`。 |
| 1 | N | 从 `AA` 到校验字节结束的线上长度，排除 Report ID 和尾部填充。 |
| 2 | AA | 帧起始标记 `AA`。 |
| 3 | GROUP | 实测请求 `12`，响应 `21`。 |
| 4 | L | 命令和数据的长度，即 `1 + 数据字节数`。 |
| 5 | CMD | 命令码。 |
| 6 起 | DATA | 依命令定义的数据。 |
| 数据后 | CHK | 对组号、长度、命令和数据求和取低 8 位。实测样例均无转义。 |

实测使用带 Report ID 的 65 字节 Windows HID 缓冲区，请求尾部补零。公开资料还记录了 `AA` 字节转义规则。实现时应依据公开资料构造转义测试向量，并用实机回包核对边界。公开资料将返回 Report ID 记为 `01`，MP305A 首版以本机实测的 `02` 为验收基线。 [公开协议记录](https://github.com/nemanjan00/pymp305/blob/main/PROTOCOL.md)

### 命令和实测帧

| 操作 | 请求 → 响应 | 证据 |
| --- | --- | --- |
| 硬件信息 | `E0 → E1` | MP305A 实测。返回型号 `MP305A`。 |
| 直流状态 | `C2 → C3` | MP305A 实测。 |
| 远程控制与输出设置 | `C8 → C9` | 根据公开协议拟定，需在 MP305A 和 MP305B 上验收。 |

以下为十六进制报文，省略尾部零填充。

```text
E0 TX  01 05 AA 12 01 E0 F3
E1 RX  02 23 AA 21 1F E1 4D 50 33 30 35 41 00 00 02 00 02 00 01 01 00 01 01 06 00 33 4D 50 33 30 35 41 00 00 00 00 4E
C2 TX  01 05 AA 12 01 C2 D5
C3 RX  02 29 AA 21 25 C3 00 00 65 00 00 60 09 00 00 88 13 05 00 00 00 00 00 00 00 00 00 00 03 00 00 00 01 01 24 00 00 01 B0 14 00 00 65
```

按公开字段表解码，上述状态帧的实测值为 0 V、0 A，设定值为 24 V、5 A，输出关闭。以下偏移从 **DATA 第一个字节**计数。 [公开协议记录](https://github.com/nemanjan00/pymp305/blob/main/PROTOCOL.md)

| 响应 | DATA 偏移 | 字段 |
| --- | --- | --- |
| `E1` | 16、20 | 应用固件版本占 4 字节，随后是 10 字节 ASCII 型号字段。 |
| `C3` | 3、5 | 实测电压、设定电压，分别为 16 位整数除以 100。 |
| `C3` | 7、9 | 实测电流、设定限流，分别为 16 位整数除以 1000。 |
| `C3` | 19、24 | 功率为 16 位整数除以 100，输出标志为单字节，`1` 表示开启。 |

公开协议中的直流控制流程为先用 `C8` 请求远程控制（`remoteCon=2`），收到 `C9` 成功状态后，再用 `remoteCon=1` 应用参数。电压编码为 10 mV 单位、电流编码为 1 mA 单位。实现阶段需确认两个型号的控制载荷、拒绝响应，以及释放远程控制后设定值和输出的行为。 [公开协议记录](https://github.com/nemanjan00/pymp305/blob/main/PROTOCOL.md)

## 验收

GitHub Actions 在 Windows、Linux 和 macOS 上执行单元测试、发布构建和版本命令检查。本项目已在 Windows x64 上验证 MP305A 的枚举、型号和状态读取，以及缺少保护配置时拒绝开启输出。MP305B 的识别与帧解析已有自动测试，实机验收待完成。实机写入和输出通断仍需按以下步骤验收。

1. 在 Windows x64 上直接运行发布的 EXE，验证帮助、版本、JSON 和错误退出码。
2. 分别连接 MP305A 和 MP305B，运行 `info` 和 `status`。核对实机面板、型号、设定值、实测值及输出状态。
3. 在空载或已知假负载下验证 `set → on → status → off → status`。确认设定阶段输出关闭，开关指令的回读与面板一致。
4. 验证断连、访问失败、异常回包和写入后读取超时的返回行为。使用本文实测帧检查长度、命令匹配、校验和单位换算。
5. 验证保护配置缺失、配置不匹配、目标值超限及输出开启时修改设定值等情形。确认 CLI 返回错误且未发送对应控制报文，并验证关闭输出仍可执行。
